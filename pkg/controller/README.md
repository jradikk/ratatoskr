# M2 gateway controller

The controller watches EgressGateway, EgressPolicy, Pod, Namespace and Secret objects across namespaces. It renders one Deployment, UDP/6081 discovery Service, and non-secret `gateway.json` ConfigMap per gateway. The Service **must not** be used as the fixed GENEVE client remote: use the healthy `status.endpoints[].podIP` (the real gateway PodIP) for admission.

Required env: `OPERATOR_NAMESPACE`, `GATEWAY_IMAGE`, `OPENVPN_IMAGE`. Optional: `IMAGE_PULL_POLICY`, `DRIVER=init`, `DATAPATH=iproute`, `SERVICE_CIDRS`, `POD_CIDRS`, `CLUSTER_DOMAIN`. The last variable is reserved for later DNS mode support. `SERVICE_CIDRS` and `POD_CIDRS` accept comma-separated IPv4 CIDRs. Use broad RBAC watch/list for gateways, policies, namespaces, pods, secrets; create/update/delete owned Deployments, Services and ConfigMaps; update gateway status; publish Events. The manager serves `/healthz` and `/readyz` on port 8081 and optionally elects a leader with `-leader-elect`.

This milestone supports **one replica, no encryption, OpenVPN upstream, cluster DNS, iproute datapath, init driver**. Other modes and policies are marked `Unsupported` and an owned Deployment is deleted rather than bypassing the VPN. The upstream Secret must contain `client.ovpn`; `auth.txt` and additional relative-path referenced files may also be present. The controller never reads or stores profile content except testing presence of that required key. The Secret is mounted only on the OpenVPN container. Upstream status comes from the gateway container's port 9900 `/info`, never from the OpenVPN loopback-only 9901 endpoint.

Client allowlists include opt-in Pods with a real IPv4 PodIP **even while Pending in an injected init container**; selected namespace labels and gateway-namespace label/annotation apply. Gateway pods have `gateway-name` and `gateway-uid` identity labels, never the workload opt-in `gateway` label. Changing selected Pod labels/IPs updates the ConfigMap; gateway binary must reload this config on update. When the gateway PodIP is lost/changed and selected clients already exist, `ClientRestartRequired=True` and a warning Event signal that **client Pod rollout is required** to replace the fixed GENEVE remote. M2 cannot transparently update an existing client netns; M5 agent mode handles that later.

The webhook sets `ratatoskr.skaldhall.io/datapath-ready=pending` on injected workload Pods. Reconciliation promotes it to `true` only after the named `ratatoskr-init` init container reports terminated exit code 0 and a valid PodIP exists. Missing/failed init reports `error`; incomplete init remains `pending`. Pods without the webhook annotation are never promoted, and gateway Pods are never touched.
